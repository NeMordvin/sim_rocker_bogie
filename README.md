# Подбор геометрии Rocker-Bogie

Streamlit-программа подбирает геометрию рычагов шестиколёсной подвески
rocker-bogie для движения по сильно пересечённой местности при заданных
габаритах (по умолчанию 1200 × 600 мм) и мотор-колёсах Xiaomi M365 Pro.

Физика считается в [MuJoCo](https://mujoco.org): контакты колёс с трением,
шарниры rocker и bogie, классический дифференциал, мотор-колёса с
ограничением пикового момента. Корпус в столкновениях не участвует.

Предыдущая версия с собственным решателем (кинематика + статика HiGHS)
сохранена в ветке `legacy-solver`.

## Запуск

Требуется Python 3.10 или новее.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
streamlit run app.py
```

## Модель

- **Колёса** — цилиндры M365 Pro (Ø216 мм, ширина 55 мм). Колея = габаритная
  ширина − ширина колеса.
- **Стойки.** Каждое колесо висит на стойке (вилка с рулевой колонкой или
  кронштейн) высотой *h* от оси до точки крепления, с наклоном *α*. У крайних
  колёс наклон зеркальный: при α > 0 верхи стоек наклонены к центру. Среднее
  колесо задаётся отдельно (α > 0 — верх вперёд).
- **Рычаги** — трубы (по умолчанию Ø40 мм) от шарниров к верху стоек.
- **Дифференциал** — угол левого rocker = −угол правого относительно корпуса.
- **Препятствия** — блоки с острой кромкой 90°: подъём на ступень, съезд со
  ступени, ров заданной глубины. Каждое — по всей ширине или только под левым
  бортом, в обоих направлениях движения.
- **Управление колёсами** — на выбор: свой регулятор скорости у каждого колеса
  или одинаковый момент всех колёс от регулятора скорости корпуса.

## Вкладки

1. **Геометрия** — параметры, схема, длины и углы труб, сохранение и загрузка
   варианта в JSON.
2. **Препятствие** — моделирование одного препятствия: результат и причина
   неудачи, покадровая анимация (вид сбоку, реакции опоры), графики реакций,
   моментов, тангажа, крена и углов bogie, экспорт GIF.
3. **Пределы** — бинарный поиск наибольших ступени, съезда и рва для текущей
   геометрии (каждый предел в своём процессе).
4. **Оптимизация** — дифференциальная эволюция SciPy по параметрам,
   отмеченным «Свободный». Оценка = Σ вес × предел (мм); для каждого
   препятствия берётся худшее направление. Варианты считаются параллельно.
5. **О модели** — описание расчёта и ограничений.

## Причины неудачи

- не хватает момента колёс — колесо упёрлось и стоит на пиковом моменте;
- пробуксовка — колёса крутятся, ровер стоит;
- задевает препятствие — касание трубы или стойки;
- опрокидывание — тангаж > 70° или крен > 40°;
- колёса висят в воздухе — подвеска не достаёт до опоры.

## Главное ограничение — момент колеса

Колесо поднимается по стенке выше своей оси только за счёт трения о стенку,
а это трение ограничено моментом мотора: `f ≤ τ/R`. Значит, нужно
`τ ≥ F·R`, где F — нагрузка на колесо. При общей массе 120 кг (F ≈ 200–300 Н)
и R = 108 мм требуется 22–32 Н·м; оценка пикового момента M365 Pro — 16 Н·м.
Геометрия лишь перераспределяет нагрузку и подталкивание, поэтому момент и
массу стоит уточнить в первую очередь.

## Тесты

```bash
python -m unittest discover -v
```

Калибровочный тест сравнивает MuJoCo с аналитическим равновесием колеса на
кромке (порог толкающей силы совпадает в пределах ±8 %). Остальные тесты
проверяют геометрию, сборку модели, прохождение ровной площадки, ступени и
съезда, баланс сил, оба режима управления, оптимизатор и запуск интерфейса.

## Ограничения

Колёса и грунт жёсткие (шина не обминается о кромку — реальное сцепление на
кромке выше), прочность, нагрев моторов и люфты не учитываются, колёса не
поворачиваются. Расчёт динамический: результат немного зависит от скорости
и способа управления колёсами.
