# Подбор геометрии Rocker-Bogie

Streamlit-программа подбирает геометрию рычагов шестиколёсной подвески
rocker-bogie для движения по сильно пересечённой местности при заданных
габаритах (по умолчанию 1200 × 600 мм) и мотор-колёсах Xiaomi M365 Pro.

Физика считается в [MuJoCo](https://mujoco.org): контакты колёс с трением,
шарниры rocker и bogie, классический дифференциал, мотор-колёса с
ограничением пикового момента. Корпус в столкновениях не участвует.

Предыдущая версия с собственным решателем (кинематика + статика HiGHS)
сохранена в ветке `legacy-solver`.

## Запуск

Требуется Python 3.10 или новее.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
streamlit run app.py
```

## Модель

- **Колёса** — цилиндры M365 Pro (Ø216 мм, ширина 55 мм). Колея = габаритная
  ширина − ширина колеса.
- **Стойки.** Каждое колесо висит на стойке (вилка с рулевой колонкой или
  кронштейн) высотой *h* от оси до точки крепления, с наклоном *α*. У крайних
  колёс наклон зеркальный: при α > 0 верхи стоек наклонены к центру. Среднее
  колесо задаётся отдельно (α > 0 — верх вперёд).
- **Рычаги** — трубы (по умолчанию Ø40 мм) от шарниров к верху стоек. Каждый
  рычаг задаётся длинами двух плеч и углом между ними. Угол отсчитывается под
  шарниром: < 180° — «домик» Λ (шарнир выше концов), 180° — прямая труба,
  > 180° — «галочка» V. У bogie плечи идут к верху стоек заднего и среднего
  колёс, у rocker — к шарниру bogie и к верху стойки переднего колеса.
  Положение шарниров и колёс вычисляется (все колёса на ровном грунте) и
  показывается для справки; если плечо не дотягивается, геометрия
  недопустима. Старые JSON-файлы с координатами шарниров переводятся
  автоматически.
- **Дифференциал** — угол левого rocker = −угол правого относительно корпуса.
- **Препятствия** — блоки с острой кромкой 90°: подъём на ступень, съезд со
  ступени, ров заданной глубины. Каждое — по всей ширине или только под левым
  бортом, в обоих направлениях движения.
- **Управление колёсами** — на выбор: свой регулятор скорости у каждого колеса
  или одинаковый момент всех колёс от регулятора скорости корпуса.

## Вкладки

1. **Геометрия** — параметры, схема с длинами плеч и углами, координаты
   шарниров и колёс для справки, сохранение и загрузка варианта в JSON.
2. **Препятствие** — моделирование одного препятствия: результат и причина
   неудачи, покадровая анимация (вид сбоку, реакции опоры), графики реакций,
   моментов, тангажа, крена и углов bogie, экспорт GIF.
3. **Пределы** — для текущей геометрии: наибольшие ступень, съезд и ров при
   моменте платформы *или* наименьший момент колеса, нужный для заданных
   препятствий (каждая граница в своём процессе).
4. **Оптимизация** — CMA-ES по параметрам, отмеченным «Свободный». Две цели:
   - *наибольшие препятствия*: оценка = Σ вес × предел (мм), для каждого
     препятствия берётся худшее направление;
   - *наименьший момент*: оценка = наибольший из моментов, нужных для
     заданных препятствий (Н·м), плюс 0,1 × средний.
5. **О модели** — описание расчёта и ограничений.

## Оптимизация

- **Цель «момент»** непрерывна: геометрия меняет требуемый момент плавно,
  а пределы в миллиметрах — ступеньками по шагу поиска (плато, на которых
  поиску не за что зацепиться). Препятствие, не проходимое и при наибольшем
  моменте (задевает, опрокидывается), считается как 2 × наибольший момент.
- **CMA-ES** (библиотека `cma`) работает в нормированных координатах [0, 1].
  Первая точка — текущая геометрия. Каждое поколение — выборка из
  многомерного нормального распределения; среднее смещается к лучшим
  вариантам, ковариация вытягивается вдоль удачных направлений, размер шага
  σ подстраивается сам. Это заметно экономнее дифференциальной эволюции для
  гладких связанных параметров (длина плеча ↔ угол).
- **Недопустимая геометрия** не моделируется и получает штраф 10⁴ + величина
  нарушения (на сколько не дотянулось плечо, вылезло за габарит и т. п.), так
  что поиск видит, куда возвращаться.
- **Подсказки границ.** Предел или момент каждого препятствия ищется от
  значения у лучшего на данный момент варианта: шаги удваиваются до смены
  результата, затем деление пополам. Это в 1,5–2 раза меньше прогонов, чем
  поиск с нуля.
- **Параллельность.** Все пары «вариант × препятствие» поколения идут в пул
  процессов сразу.
- **Уточнение.** Несколько лучших вариантов в конце пересчитываются с шагом
  поиска в 2,5 раза мельче; в таблице результатов они идут первыми.

## Причины неудачи

- не хватает момента колёс — колесо упёрлось и стоит на пиковом моменте;
- пробуксовка — колёса крутятся, ровер стоит;
- задевает препятствие — касание трубы или стойки;
- опрокидывание — тангаж > 70° или крен > 40°;
- колёса висят в воздухе — подвеска не достаёт до опоры.

## Главное ограничение — момент колеса

Колесо поднимается по стенке выше своей оси только за счёт трения о стенку,
а это трение ограничено моментом мотора: `f ≤ τ/R`. Значит, нужно
`τ ≥ F·R`, где F — нагрузка на колесо. При общей массе 120 кг (F ≈ 200–300 Н)
и R = 108 мм требуется 22–32 Н·м; оценка пикового момента M365 Pro — 16 Н·м.
Геометрия лишь перераспределяет нагрузку и подталкивание, поэтому момент и
массу стоит уточнить в первую очередь.

## Тесты

```bash
python -m unittest discover -v
```

Калибровочный тест сравнивает MuJoCo с аналитическим равновесием колеса на
кромке (порог толкающей силы совпадает в пределах ±8 %). Остальные тесты
проверяют геометрию, сборку модели, прохождение ровной площадки, ступени и
съезда, баланс сил, оба режима управления, поиск границ с подсказкой,
требуемый момент, перевод старых координат в плечи и углы, оптимизатор и
запуск интерфейса.

## Ограничения

Колёса и грунт жёсткие (шина не обминается о кромку — реальное сцепление на
кромке выше), прочность, нагрев моторов и люфты не учитываются, колёса не
поворачиваются. Расчёт динамический: результат немного зависит от скорости
и способа управления колёсами.
